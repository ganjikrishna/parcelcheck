Write a single JavaScript file, worker.js, a Cloudflare Worker for ParcelCheck, a land diligence checker. No imports; use the standard Worker fetch API and a Durable Object class exported from the same file. The Worker serves a static page via env.ASSETS and runs live checks at POST /check.

Constants: MODEL "muse-ember-1.0"; API https://api.meta.ai/v1/responses; rates input $0.10 per million tokens, output $0.50 per million; MAX_TEXT 20000; DAILY_CAP 200. The Ember system prompt is the string literal placeholder __PROMPT_V1_SYSTEM__ placed exactly once where the system prompt constant goes (a deploy step replaces it with the frozen prompt text): const SYSTEM_PROMPT = "__PROMPT_V1_SYSTEM__"; The API key is env.META_API_KEY. The nine points in order: access, flood, perc_septic, water_well, liens_tax, zoning, utilities, mineral_timber, survey. Statuses: problem_stated, clean, missing.

parseJson(text): strip; remove a wrapping code fence if present; try JSON.parse; on failure scan every "{" position and use a small recursive approach: try JSON.parse of progressively shorter substrings is NOT allowed; instead find the first complete object carrying a top-level "checks" key by scanning with a brace-matching decoder equivalent (implement a JSONDecoder-style scan: for each "{" index, attempt to decode one JSON value starting there using a hand-written parser or JSON.parse on balanced-brace substrings; return the first decoded object with a "checks" key; otherwise throw).

validate(result, listingText): same rules as the Python harness. Errors: checks not a list of exactly 9 ("checks must be a list of exactly 9", return immediately); unknown point; bad status; problem_stated or clean with no evidence; any evidence quote not an exact substring of listingText (error text begins with the point and "FABRICATED QUOTE"). Warnings: missing check carrying evidence; red_flags points set differs from problem_stated points; missing_items set differs from missing points; missing points without a seller question.

applyRules(result): the liens rule, JavaScript mirror of the Python harness, identical keyword lists and identical strings. For a liens_tax check with status clean: evidence joined and lowercased; taxHalf = contains "tax" and any of ["paid","current","through","up to date","up-to-date","not delinquent","no delinquent"]; lienHalf = contains "lien" and any of ["no lien","free of lien","free and clear","clear of lien","without lien","no recorded lien","lien free","lien-free","not subject to lien"]. If NOT (taxHalf && lienHalf): status becomes missing; note gets " Harness rule: only one half of this point (taxes or liens) is stated, so it counts as not fully addressed." appended; ensure liens_tax in missing_items; if no liens_tax seller question, append {"point":"liens_tax","question":"Are all property taxes paid through the current year, and are there any liens, judgments, or back taxes on this parcel?"}; record "liens_tax_clean_requires_both_halves". Return applied rule names.

runCheck(env, listingText, listingId): user message exactly "Check this listing against the nine points. Return only the JSON object.\n\n<listing id=\"ID\">\nTEXT\n</listing>". POST the API with model, input [system SYSTEM_PROMPT, user], max_output_tokens 12000, store false, Authorization Bearer env.META_API_KEY. Non-OK response throws "Ember API <status>". Concatenate output_text content. parseJson, applyRules, validate; if errors non-empty throw "Validation failed: <first error>". Attach cost {usd rounded to 6dp, input_tokens, output_tokens, model} and harness {errors, warnings, seconds (1dp), prompt_version "v1", rules_applied}. Return result.

Records mode. fetchJson(url, opts, timeoutMs=7000): fetch with AbortSignal.timeout, throw on non-OK, return JSON.
looksLikeAddress(text): trimmed length <= 200 chars and <= 22 words, contains a digit, and contains a comma OR a 5-digit ZIP (with optional -4).
extractAddress(text): regex match for a US street address inside longer text: 1-6 digits, street name words, a street suffix (St|Street|Ave|Avenue|Rd|Road|Dr|Drive|Ln|Lane|Blvd|Hwy|Highway|Ct|Court|Cir|Circle|Way|Trl|Trail|Pkwy|Parkway), optional text up to the comma, then city words, comma, 2-letter state, 5-digit ZIP. Return the match trimmed or null.
geocode(address): GET https://geocoding.geo.census.gov/geocoder/locations/onelineaddress with params address, benchmark Public_AR_Current, format json. Return null if no addressMatches; else {matched: matchedAddress, lat: coordinates.y, lng: coordinates.x}.
femaLine(lng, lat): ArcGIS point query (geometry "lng,lat", geometryType esriGeometryPoint, inSR 4326, spatialRel esriSpatialRelIntersects, outFields FLD_ZONE,ZONE_SUBTY,SFHA_TF, returnGeometry false, f json) against https://hazards.fema.gov/arcgis/rest/services/public/NFHL/MapServer/28/query with browser headers (Mozilla User-Agent, Accept application/json, Referer https://hazards.fema.gov/). On fetch failure: wait 900 ms, retry the same URL once; on second failure use the mirror https://hazards.fema.gov/arcgis/rest/services/FIRMette/NFHLREST_FIRMette/MapServer/20/query. No features: return "FEMA National Flood Hazard Layer: no flood hazard data is published for this point." Else build: "FEMA National Flood Hazard Layer: the flood zone at this point is Zone <FLD_ZONE>" plus ", <ZONE_SUBTY lowercased>" if present, plus "."; if SFHA_TF is "T" append " This point is in a Special Flood Hazard Area, with a 1 percent or greater annual chance of flooding. Flood insurance is required for buildings with federally backed mortgages in this area." else append " This point is not in a Special Flood Hazard Area."
wetlandsLine(lng, lat): same style query, outFields WETLAND_TYPE, against https://fwspublicservices.wim.usgs.gov/wetlandsmapservice/rest/services/Wetlands/MapServer/0/query. No features: "US Fish and Wildlife Service National Wetlands Inventory: no wetlands are mapped at this point." Else "US Fish and Wildlife Service National Wetlands Inventory: a mapped wetland is present at this point (type: <WETLAND_TYPE or 'wetland'>). Building or filling in a mapped wetland can require federal permits."
sda(sql): POST https://SDMDataAccess.nrcs.usda.gov/Tabular/post.rest, form body QUERY=sql, FORMAT=JSON+COLUMNNAME, timeout 9000; return the Table rows after the header row.
soilLines(lng, lat): subquery (SELECT mukey FROM SDA_Get_Mukey_from_intersection_with_WktWgs84('POINT(<lng> <lat>)')). First query muname from mapunit; none -> []. First line "USDA soil survey: the soil at this point is <muname>." Second query: component name, comppct_r, drainagecl, and cointerp interplrc with ruledepth 0 and rulename 'ENG - Septic Tank Absorption Fields', ordered by comppct_r desc. If rows: if drainagecl, add "USDA soil survey: the main soil component (<name>, <pct> percent of the area) has a drainage class of <drainagecl lowercased>." If the septic rating exists and is not "Not rated", add "USDA soil survey: this soil is rated for septic tank absorption fields as: <rating>." ("Not rated" is omitted deliberately; it carries no septic information.)
buildRecords(address): geocode; null if unmatched. Run femaLine, wetlandsLine, soilLines concurrently with allSettled; collect fulfilled string results into lines and array results spread into lines; sources starts ["US Census Bureau geocoder"] and adds the source name of each job that produced lines ("FEMA National Flood Hazard Layer", "US Fish and Wildlife Service National Wetlands Inventory", "USDA soil survey"). Compute facts: floodLine = the line starting "FEMA National Flood Hazard Layer" or null; septicLine = the line containing "rated for septic tank absorption fields as:" or null; floodHazard = floodLine contains "This point is in a Special Flood Hazard Area"; septicRating = the text after "rated for septic tank absorption fields as:" in septicLine, trimmed, trailing period removed. Return {matched, lat, lng, lines, sources, facts}.
applyRecordsOverride(result, facts): if facts missing, return. Using result.harness.rules_applied (create if absent): flood check clean AND facts.floodHazard AND facts.floodLine -> status problem_stated, evidence [floodLine], note "The listing does not flag a flood problem, but FEMA records put this point in a Special Flood Hazard Area. The record is the flag.", source "records", add red flag {point "flood", summary "FEMA records: Special Flood Hazard Area", quote floodLine} if absent, remove flood from missing_items, remove any flood seller question, record "records_override_flood". perc_septic check clean AND facts.septicLine AND rating is "Somewhat limited" or "Very limited" -> status problem_stated, evidence = existing evidence plus septicLine, note "The listing's perc position reads clean, but USDA soil data rates this soil <rating> for septic absorption. Both are shown; the records rating is the flag.", source "records", add red flag {point "perc_septic", summary "USDA soil rating: <rating> for septic absorption", quote septicLine} if absent, remove from missing_items, remove its seller question, record "records_override_perc_septic". Only ever upgrades clean; never touches missing or problem_stated.
tagRecordsSources(result, listingText): for each check with non-empty evidence where EVERY quote is NOT a substring of listingText, set check.source = "records".

runSmart(env, text, id):
1. If looksLikeAddress(text): buildRecords(text); if records with lines: recordsText = "Public records check for the property at: <matched>\nCoordinates of the point checked: latitude <lat>, longitude <lng>.\n<lines joined by newline>\nThis text is compiled from live public records, not from a seller listing. It covers only the points the records speak to. Anything the records do not cover is not addressed here and still needs the seller or the county." runCheck(recordsText, "address"), applyRecordsOverride, mode "records", matched_address, sources; return.
2. Else extractAddress(text); if found: buildRecords(addr); if records with lines: combined = text + "\n\nPUBLIC RECORDS CHECKED TODAY for the address in this listing (<matched>):\n" + lines joined. runCheck(combined, id), applyRecordsOverride, tagRecordsSources(result, text), mode "listing+records", matched_address, sources; return.
3. Else runCheck(text, id), mode "listing"; if looksLikeAddress(text) was true but records failed, records_note = "That looked like an address, but it was not found in the US public records ParcelCheck uses, so records were not checked. It was read as listing text instead. ParcelCheck covers US addresses."; else if an address was extracted but records failed, records_note = "An address was found in the text, but public records were not checked for it. This report covers the listing text only." Return.

RunCounter Durable Object: storage key "state" {day, count}; new UTC day resets; if count >= DAILY_CAP return JSON {ok:false}; else increment, store, return {ok:true, count}.

Default export fetch: POST /check only; parse JSON body (400 {"error":"Bad request."} on failure); text = body.text trimmed; empty -> 400 "Nothing to check yet. Paste a listing, or type a street address with city and state."; over MAX_TEXT -> 400 "That text is over 20000 characters. Paste the listing description and its fields, not the whole page."; input gate: if NOT looksLikeAddress(text): under 8 words -> 400 "That is too short to check. Paste a full listing, or type a street address with city, state, and ZIP."; and if no digit AND no listing keyword (acre|land|sale|sold|price|road|lot|property|zoning|well|septic|tax|parcel|county|bed|bath, case-insensitive) -> 400 "That does not look like a listing or an address. Paste a full listing, or type a street address with city, state, and ZIP." Then the Durable Object cap check (env.RUN_COUNTER, name "global"); cap full -> 429 "Daily live run cap reached. Cached examples still work." Then runSmart with body.id or "web"; success 200 JSON; exception -> 502 "Checker run failed: <first 200 chars>". All other requests: env.ASSETS.fetch(request). JSON responses use content type application/json; charset=utf-8.

Correction pinned after a failed live test (read carefully): in soilLines, the USDA component table's name column is "compname", NOT "name"; selecting c.name makes the soil query fail on the live service. Use a LEFT JOIN from component to cointerp ON cointerp.cokey = component.cokey AND cointerp.ruledepth = 0 AND cointerp.rulename = 'ENG - Septic Tank Absorption Fields' (a plain inner JOIN drops components that have no septic row). And soilLines must be failure-tolerant in parts: if the second (component) query fails, still return the lines already built from the first query; only a failure of the first mapunit query returns []. A records source that throws must never take down lines already earned.

Second correction pinned after a regeneration regression (read carefully): the US Census geocoder response nests its matches at data.result.addressMatches. Reading data.addressMatches directly always finds zero matches and silently disables all of records mode. geocode must read (data.result || {}).addressMatches. Do not regress the soil fixes above while applying this: compname, LEFT JOIN, and partial-failure tolerance in soilLines all stay.
