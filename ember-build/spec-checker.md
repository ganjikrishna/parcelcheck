Write a Python 3 file, checker.py, the core of ParcelCheck, a land listing diligence checker. Standard library only.

Purpose: send one land listing to the Muse Ember model with a frozen prompt, validate the model's structured answer in a harness, and log a trace of every run.

Constants and setup:
- The script's data folder ("prep") is the PARCELCHECK_DIR environment variable if set, else the folder containing the script file.
- API endpoint: https://api.meta.ai/v1/responses. Model: muse-ember-1.0. Rates for cost math: input $0.10 per million tokens, output $0.50 per million.
- The nine points, in order: access, flood, perc_septic, water_well, liens_tax, zoning, utilities, mineral_timber, survey. Valid statuses: problem_stated, clean, missing.

Function call_ember(system, user, max_out=8000): read the API key from meta-api-key.txt in prep (strip whitespace). POST JSON {"model": MODEL, "input": [{"role":"system","content":system},{"role":"user","content":user}], "max_output_tokens": max_out, "store": false} with header Authorization: Bearer <key> and content type application/json, timeout 300. From the response JSON, concatenate the text of every content item of type output_text inside output items of type message. Return (text, input_tokens, output_tokens, elapsed_seconds_rounded_1dp) using the response usage object.

Function parse_json(text): strip whitespace; if the text starts with a code fence, remove the opening fence line and a trailing fence. Try json.loads. On failure, scan every position of "{" in the text, raw-decode an object starting there, and return the first complete decoded object that is a dict carrying a top-level "checks" key; if none, re-raise the original error. (This handles model replies with prose after the JSON or a schema echoed before the result.)

Function apply_rules(result): one deterministic rule, recorded openly. For the check whose point is liens_tax, if its status is clean: join its evidence quotes with spaces and lowercase. Define tax_half: the text contains "tax" AND any of: paid, current, through, up to date, up-to-date, not delinquent, no delinquent. Define lien_half: the text contains "lien" AND any of: no lien, free of lien, free and clear, clear of lien, without lien, no recorded lien, lien free, lien-free, not subject to lien. If NOT (tax_half AND lien_half): set the check status to missing; append to its note the sentence "Harness rule: only one half of this point (taxes or liens) is stated, so it counts as not fully addressed."; ensure "liens_tax" is in result missing_items; if no seller question exists for liens_tax, append {"point": "liens_tax", "question": "Are all property taxes paid through the current year, and are there any liens, judgments, or back taxes on this parcel?"}; record the rule name "liens_tax_clean_requires_both_halves". Return the list of applied rule names. Include a docstring explaining the rule: liens and tax status counts as clean only when the evidence covers both halves (taxes stated paid or current, liens stated clear), per checklist section 5, and a phrase covering neither half (for example "no tax liens") counts for neither.

Function validate(result, listing_text): returns (errors, warnings), never edits. If checks is not a list of exactly 9, return one error "checks must be a list of exactly 9" immediately. For each check: unknown point name is an error; status not in the valid set is an error; a problem_stated or clean check with no evidence is an error; a missing check carrying evidence is a warning; every evidence quote must appear as an exact substring of listing_text, else an error beginning "FABRICATED QUOTE". After the loop, if the set of seen points is not all nine, an error. Consistency warnings (not errors): the set of red_flags points differs from the problem_stated points; the set of missing_items differs from the missing points; any missing point lacks a seller question (warning naming the points).

Function check(listing_text, listing_id): load prompt-v1.json from prep (keys: version, model, system). Build the user message exactly: "Check this listing against the nine points. Return only the JSON object.\n\n<listing id=\"LISTING_ID\">\nLISTING_TEXT\n</listing>". Call call_ember with the system text and max_out 12000. If parse_json raises: append a trace line to runs.jsonl in prep with fields ts (strftime "%Y-%m-%dT%H:%M:%S%z"), listing_id, prompt_version, model, input_tokens, output_tokens, usd (rounded 6dp), error ("parse failure: " plus the exception), raw_head (first 400 chars of the raw reply); also append the same JSON plus the full raw reply to failed-runs.log; then re-raise. On success: apply_rules, then validate. Set result["cost"] = {"usd":..., "input_tokens":..., "output_tokens":..., "model": MODEL}. Set result["harness"] = {"errors":..., "warnings":..., "seconds": elapsed, "prompt_version":..., "rules_applied":...}. Append a trace line to runs.jsonl with fields ts, listing_id, prompt_version, model, input_tokens, output_tokens, usd, errors, warnings, rules_applied. Return the result.

CLI: python3 checker.py <listing-file> [listing-id], or python3 checker.py --text '<text>' [listing-id]. For a file: if the content contains a blank line, the listing text is everything after the first blank line, stripped (files carry a source header above the excerpt); the id defaults to the file stem. For --text the id defaults to "adhoc". Print the result as indented JSON to stdout.

Module docstring at the top describing the tool, its usage, that it reads the API key and frozen prompt from its own folder (PARCELCHECK_DIR override), and appends one trace line per run to runs.jsonl.
