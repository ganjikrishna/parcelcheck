Write a single HTML file, index.html, the ParcelCheck web page. One file, inline CSS and JavaScript, no external assets. It talks to POST /check on the same origin and to three cached example files.

Design: a diligence report, not a tech landing page. Warm paper background (#f7f2e9 or similar), serif display type for headings (Georgia, 'Times New Roman', serif), sans body, deep green primary (#1d4d33), rust accent (#b3401e), thin ruled borders, small caps section labels, no gradients, no shadows-heavy styling, no emojis. Max content width about 860px, generous margins, mobile friendly.

Content structure:
1. Header: the name "ParcelCheck" and the tagline "Know what the listing is not telling you, for pennies." A short paragraph: paste a land listing, or type just an address, and get a nine point diligence report; every red flag quotes its source word for word; what the text never says becomes the questions to ask. A line noting it runs on Muse Ember and each live check costs a fraction of a cent.
2. The nine points listed by name: Legal road access; Flood zone; Perc test and septic; Water source and well; Liens and tax status; Zoning; Utilities at the lot; Mineral and timber rights; Survey and boundaries.
3. One input box (textarea) with a placeholder inviting a listing paste or an address, and a "Run the check" button. Below it, three example cards, each a button with a tag line, a title, and a one line sub:
   - Example 01 · Cached result / "Landlocked in Florida" / "One acre near Krome Avenue, Miami-Dade. The listing buries the access problem mid paragraph." (data-example L01)
   - Example 02 · Cached result / "Clean-looking in Georgia" / "5.65 acres in Carlton with a drilled well and an approved perc test. USDA soil records flag the septic rating behind that perc, and FEMA backs the flood answer." (data-example L07)
   - Example 03 · Address only · Cached result / "An address in Miami Beach" / "No listing at all. Just an address, checked against live FEMA flood records: Zone AE, a flood problem." (data-example MB)
   Clicking a card fills the textarea with the matching full listing text (an object in the script holding the three texts; the Miami Beach card fills the address "1700 Convention Center Dr, Miami Beach, FL 33139") and renders the cached result fetched from '/cached-<id>.json?v=20261125c'. Cached results render through the same render function as live results, marked as a cached example.
4. A "How it works" section: one structured Muse Ember pass against a nine point checklist written from real land diligence; a harness validates every answer before it is shown (nine points, quotes must appear word for word in the source text, flags and questions consistent); when the text contains a US address, live public records (US Census geocoder, FEMA flood layer, USDA soil survey, US Fish and Wildlife wetlands inventory) are checked too and merged into the same report; records can fill silence but are never invented; a live run counter line and honest limits (it reads text and records, it does not visit the land).
5. Footer: built for the Meta Muse Ember Hackathon; solo entry; link placeholders are not needed beyond text.

Behavior:
- Submit: POST /check with JSON {text}. While waiting, the button disables and reads "Checking...". On an error response, show the error message plainly in the report area. On success, render the report.
- The example texts object: L01 is a Florida land listing whose text contains "0 SW 52nd Street, Unincorporated, FL" and describes one acre near Krome Avenue with no legal road access stated in a buried sentence (write a realistic full listing text of about 120 words carrying those facts); L07 is the Carlton, Georgia listing: "55 Dora Bush Hill Road, Carlton, GA 30627, Price: $125,000. Lot size: 5.65 Acres. County: Oglethorpe. Taxes: $660.48. Utilities: Cable Available, Electricity Available. Water: Private, Well. Sewer: Perc Test On File." plus a marketing paragraph about a beautiful 5.65 acre wooded tract with a drilled well, designated building site, and an approved perc test, about 30 minutes from Athens, Georgia. MB is exactly "1700 Convention Center Dr, Miami Beach, FL 33139".
- Render function for a result object {checks: [{point, status, evidence[], note, source?}], red_flags: [{point, summary, quote}], missing_items: [point], seller_questions: [{point, question}], cost: {usd, input_tokens, output_tokens}, mode, matched_address?, sources?, records_note?}:
  - A summary line: mode wording (listing only / address records only / listing plus live records), the matched address when present, and the run cost formatted like $0.0036.
  - If records_note present, show it as a visible note box.
  - "Red flags, in their own words": each flag with its point name, summary, and the quote in a blockquote style. If none: for mode listing, "The listing states no red flags. That is not the same as a clean parcel; read what it leaves out, below." For records or combined modes, "No red flags stated in the listing or the records. That is not the same as a clean parcel; read what is left out, below."
  - Seller questions split in two groups: questions whose point is NOT in missing_items render under "Worth a follow-up, on points that are stated"; questions for missing points render under the heading "Still to verify" when mode is records, else "Ask the seller". Each question shows its point name and the question text.
  - "All nine points": a grid with one cell per check: point name, a status chip (red "Problem stated", green "Clean", amber "Not addressed"), the note, and when check.source is "records" the words "(Public records)" appended in bold after the note.
  - If sources present, a line "Records sources: ..." joining them.
- Escape all result text before inserting it as HTML (an esc() helper using textContent or entity replacement). Never inject raw result strings as HTML.
- Point display names map: access "Legal road access", flood "Flood zone", perc_septic "Perc and septic", water_well "Water and well", liens_tax "Liens and taxes", zoning "Zoning", utilities "Utilities", mineral_timber "Mineral and timber rights", survey "Survey and boundaries".
